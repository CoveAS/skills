---
name: stating-problems
description: "Writes a short problem brief in a fixed shape: one problem sentence, numbered facts, the current behaviour, the desired behaviour, and the key files in priority order. Use when the user asks what the problem is, asks for a problem statement or a brief, or invokes /stating-problems."
---
Write the brief in this order. Keep every part short.

1. The problem. One sentence.
2. The facts. A numbered list, at least 1 item and at most 5. One short line each.
3. The current behaviour. One line.
4. The desired behaviour. One line.
5. The files. A numbered list in priority order, the most important first. Give the path, the line numbers and an extremely short reason.

Read the code before you write the file list. Give real line numbers.

Put the whole brief in one markdown code block. The user copies it out.

Write nothing else. No preamble, no summary, no plan.
